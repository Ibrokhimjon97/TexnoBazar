# Receipt-bound branch-transfer settlement with prepayment ledger

The change moves branch-transfer ownership and debt recognition to destination receipt, while allowing dated payments before or after receipt. Transfer lines are pinned to canonical wholesale prices, shipping retains the source reservation, and receipt atomically moves units, creates the debt, and links prepayments. The manager UI adds unit search, initial and subsequent payments, settlement history, and richer debt detail. **[confirmed]** The migration cannot upgrade a database that already has debt payments; **[confirmed]** unconstrained currency selection can also create materially incorrect debt principal.

Watch for: **[confirmed]** the payment backfill runs before the old immutable trigger is removed; **[confirmed]** user-selected transfer currency is not tied to canonical wholesale-price currency; **[likely]** paid transfers can be cancelled into an un-settleable state; **[likely]** wholesale value is written into inventory movement cost fields.

**Verdict**: NEEDS_CHANGES

## High-level view

The lifecycle keeps `active_transfer_id` as the reservation through shipping and moves the unit only at receipt. **[confirmed]** This matches the stated ownership boundary, but the migration ordering prevents existing payment data from reaching the new lifecycle.

Settlement uses a transfer-scoped payment ledger before receipt and a debt-scoped view afterward. **[confirmed]** Transfer row locking serializes receipt and payment writes; **[likely]** cancellation and **[confirmed]** replay comparison do not cover every state and field introduced by prepayment.

Wholesale enforcement prevents arbitrary numeric line prices. **[confirmed]** It does not bind those values to a currency, while the UI can attach UZS, USD, or EUR; **[likely]** receipt also mixes settlement value with inventory cost basis.

The browser contracts add search and dual idempotency keys. **[likely]** The create helper breaks its prior third-argument contract; **[confirmed]** search has a nullable limit escape hatch and a hard-coded USD display path.

## Existing payment history blocks the migration

**[confirmed]** The migration backfills existing rows at `supabase/migrations/20260902800000_branch_transfer_settlement.sql:8`, but does not drop the pre-existing immutable update trigger until line 56. Under the supplied schema contract, the trigger rejects this update, so migration succeeds only when `debt_payments` is empty. Drop or replace the trigger before backfill, then install the new guard after `transfer_id` is populated and constrained.

```sql
update public.debt_payments ...;              -- old immutable trigger still active
...
drop trigger if exists debt_payments_immutable ...;
```

**[confirmed]** No supplied test exercises an upgrade with an existing debt/payment, trigger replacement, receipt linking, or rollback after failure. Add a seeded migration test for this conversion.

## Receipt valuation uses settlement price as inventory cost

**[likely]** Both receipt movements write `v_line.unit_price` into `inventory_movements.unit_cost` at lines 278 and 289. The line-price trigger guarantees this is wholesale price, while unit lookup separately exposes actual `cost_price`; if `unit_cost` feeds valuation or margin reporting, receipt revalues movement history at wholesale. Keep debt principal at wholesale, but write batch/product cost basis to inventory movements unless `unit_cost` is explicitly a settlement-value field.

## Canonical numeric prices can take an arbitrary currency

**[confirmed]** `enforce_transfer_wholesale_price` only compares `transfer_lines.unit_price` with the batch/product wholesale number. `TransferWorkspace.jsx:151` independently offers UZS, USD, and EUR, and no supplied server code validates that header currency against the wholesale-price currency. A value such as `1,000,000` can therefore become UZS, USD, or EUR debt principal while passing the price trigger. Derive currency from the canonical pricing source or reject mismatches server-side, then display the derived currency rather than an unconstrained selector.

## Prepayments lack a cancellation settlement policy

**[likely]** Payments are accepted in every transfer status except `cancelled` at migration line 189, and `can_record_payment` follows the same rule. This change adds no guard to stop an already-paid requested/approved transfer from being cancelled and no reversal or debt path when receipt never occurs. If the existing cancellation transition remains available, immutable payments can be stranded on a cancelled transfer without a `branch_debt`; reject such cancellation or atomically record an explicit refund/reversal.

## Payment intent and replay are not equivalent

**[confirmed]** `record_branch_transfer_payment` compares amount, currency, method, reference, and notes for an existing idempotency key, but omits `paid_at` at lines 183–186. A retry with a different date returns success while retaining the old date. Compare the normalized effective timestamp; if null means server time, define a stable replay rule for null.

**[confirmed]** `create_branch_transfer_with_payment` only records the parsed initial payment when `coalesce(v_amount,0)>0` at line 224. A supplied object with a missing, zero, or negative amount succeeds as a transfer with no payment. Reject non-null payment objects whose amount is not positive instead of treating malformed intent as absence of payment.

## Search and browser contracts bypass their intended bounds

**[confirmed]** `search_transfer_units` checks `p_limit not between 1 and 50`, but null passes through SQL three-valued logic and `LIMIT NULL` removes the cap from this security-definer query. Reject null explicitly or apply a bounded `coalesce` default.

**[likely]** `packages/data/src/transfers.js:22` changes `createBranchTransfer` from `(header, lines, idempotencyKey)` to `(header, lines, initialPayment, keys)`. A caller using the old contract sends its UUID as a JSON scalar payment and fails server validation. Preserve an overload or update and verify every package consumer.

**[confirmed]** `TransferWorkspace.jsx:203` forces search-result wholesale prices through the USD formatter and strips the suffix, including for UZS/EUR transfers. Pass the selected currency into `TransferSearchResults` and show the denomination explicitly.
