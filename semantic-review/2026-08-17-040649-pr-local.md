# CMS-driven storefront va inventory katalogga nashri

Bu o‘zgarish storefront kontenti, navigatsiyasi va SEO sozlamalarini superadmin builder orqali boshqaradi, katalogni public RPC read-modellari bilan beradi va real ombor birliklari mavjud mahsulotlarni bulk nashr qiladi. Storefront data layer katalog, CMS va reference ma’lumotlari uchun RPC ishlatadi; inventory publish yangi product yaratmaydi, mavjud `products.id` qatorini `active/published` qiladi. Banner media lifecycle verified upload, attach va cleanup queue orqali qurilgan. Biroq public settings disclosure allow-list bilan bir xil chegaraga ega emas va builderda tanlanadigan bir necha placement/navigation contractlari storefrontda bajarilmaydi.

Watch for: **[HIGH, confirmed]** public settings va direct CMS read yuzasi explicit storefront allow-listni chetlab o‘tadi; **[HIGH, confirmed]** `home_promo`, `catalog_top`, `mobile` va child menu konfiguratsiyalari saqlanadi, lekin render qilinmaydi; **[MEDIUM, confirmed]** async admin loads eski response bilan yangi filter holatini bosishi mumkin.

**Verdict**: NEEDS_CHANGES

## High-level view

Public storefront JavaScript katalog, CMS va references uchun RPC chaqiradi, lekin database policies CMS va `system_settings` direct selectini ham ochiq qoldiradi. `storefront_cms_payload` settingsni yangi builder allow-listi bilan emas, `is_public` flagi bilan chiqaradi, shuning uchun public disclosure chegarasi mutation chegarasidan kengroq.

Banner duplicate yangi ID va media talab qiladi; failed save objectni cleanupga yuboradi, replacement eski objectni queuega qo‘yadi, quick visibility esa mavjud mediani saqlaydi. Builder taklif qiladigan ikki banner placementi, mobile-only menu va parent/child menu topologiyasi storefront rendereriga ulanmagan.

Barcha besh home block turi uchun renderer branch mavjud. `products` block va promotion membership esa nom bo‘yicha yuklangan dastlabki 100 product cache ichidan yechiladi, shuning uchun valid CMS selection jim yo‘qolishi mumkin.

Inventory candidate va bulk publish active store/warehouse locationdagi `available`, transferda bo‘lmagan unitlarni ishlatadi. RPC admin rolini va publishabilityni qayta tekshiradi, mavjud productni update qiladi hamda per-item partial natija beradi; UI failure tafsilotlarini yo‘qotadi va stale requestlardan himoyalanmagan.

Responsive qatlamda product cardning nested interactive modeli klaviatura aktivatsiyasini chalkashtiradi, ayrim icon-only controllarda accessible name yo‘q va uchta service uchun to‘rt ustunli desktop grid ajratilgan.

## Public CMS read boundary builder allow-listidan kengroq

**[HIGH, confirmed]** `get_storefront_site_settings_admin` va `save_storefront_site_settings` explicit key allow-listini ishlatadi (`20260823000000_storefront_builder_inventory_publish.sql:14-18, 32-36`), ammo public `storefront_cms_payload` barcha `is_public` settinglarni chiqaradi (`20260113000000_complete_business_workflows.sql:1466`). `public_settings_user_read` va CMS public policies anon/authenticated direct table readsga ham ruxsat beradi (`20260101000000_initial_schema.sql:678-685`). Frontend direct tablega tayanmaydi (`packages/data/src/storefront.js`), ammo public disclosure boundary RPC allow-listi bilan mustahkamlanmagan. Payload settings querysini aynan builder allow-listiga cheklash, strict RPC-only model talab qilinsa anon direct CMS/system_settings accessni olib tashlash kerak.

Admin mutations global admin tekshiruviga ega: settings va banner/promotion SECURITY DEFINER RPClari role/payload preflight qiladi, qolgan CMS direct CRUD esa admin-all RLS policy bilan cheklangan (`20260101000000_initial_schema.sql:733-736`). ## Inventory preflight va partial result contracti

Candidate va publish RPClari `require_catalog_admin` bilan boshlanadi (`20260823000000_storefront_builder_inventory_publish.sql:73,124`). Candidate active store/warehousedagi `available`, transferda bo‘lmagan unitsni sanaydi (`:86-88,101-103`); publish availability, active category/brand, positive retail price va primary media/required attributesni qayta tekshiradi (`:132-143`). Publish insert emas, `products.id` bo‘yicha update qiladi (`:142`), per-item exception block esa failed itemni rollback qilib qolganlarini davom ettiradi (`:145-150`). Bu duplicate yaratmaslik, role, stale-preflight va partial-success contractlarini qoplaydi.

**[MEDIUM, confirmed]** frontend `response.results`dagi product ID/errorlarni ko‘rsatmaydi va barcha selectionni tozalaydi (`ProductCatalog.jsx:26`). Failed rows sababini ko‘rsatish va ularni retry uchun selected qoldirish kerak.

**[LOW, confirmed]** candidate aggregation total va page uchun ikki marta takrorlangan (`20260823000000_storefront_builder_inventory_publish.sql:77-107`). Katta `inventory_units` hajmida buni bitta query/window countga yig‘ish kerak.
