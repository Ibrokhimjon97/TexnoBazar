# Storefront CMS reachability fixes with a remaining hierarchy gap

This pass re-checks the three prior CMS reachability findings and the previously resolved storefront, security, publishing, concurrency, and interaction behaviors. Product hydration now covers every deduplicated ID in batches of at most 100, CMS mobile navigation closes the drawer, and footer children render. The builder and migration validate a child’s selected parent, but changing a root that already has children can still leave those children attached to a cross-location or non-root parent. The other previously resolved behaviors remain intact.

Watch for: **[MEDIUM, confirmed]** the menu trigger validates the row being written but not its existing children, so editing a parent can recreate the hierarchy states that the migration initially normalizes.

**Verdict**: NEEDS_CHANGES

**Review decision**: CHANGES REQUESTED

## High-level view

CMS product references no longer stop after one RPC-sized group. The adapter deduplicates IDs and walks the complete set in 100-item batches, and the home page merges the complete result.

Customer navigation now reaches CMS hierarchy consistently: CMS targets close the mobile drawer centrally, and footer roots render their same-location children. The remaining gap is parent mutation: neither the builder nor database trigger prevents a root with children from moving locations or becoming a child itself.

The public CMS trust boundary remains RPC-only for anonymous clients, with an explicit settings allow-list and revoked direct table reads. Hero, `home_promo`, and `catalog_top` records each have a customer-facing placement.

Partial bulk publishing retains failed IDs and failure details across refreshes. Product, inventory, and storefront catalog requests reject stale responses, product filters reset pagination, and ProductCard navigation remains separate from its favorite action.

## Complete CMS product hydration and reachable customer navigation

`loadStorefrontProducts` string-normalizes and deduplicates every supplied ID, then loops through the full set with `slice(offset, offset + 100)` and accumulates every batch. This resolves the prior permanent omission of references after the first 100.

`navigateTarget` closes the menu before handling internal, external, or malformed destinations, so mobile CMS root and child actions dismiss the drawer. `Footer` now emits `footerChildren(item)` after each root, making valid footer children reachable.

## Menu enforcement misses edits to an existing parent

The builder limits parent options to same-location roots, clears an incompatible selected parent when an item’s location changes, and validates that selected parent again on submit (`apps/superadmin/src/CmsWorkspace.jsx:55-62`). The migration normalizes existing invalid children and its trigger rejects a child row whose selected parent is missing, nested, or in another location (`supabase/migrations/20260823000000_storefront_builder_inventory_publish.sql:159-180`).

**[MEDIUM, confirmed]** those checks only validate the item currently being edited. A root with existing children can change from `header` to `footer`; because its own `parent_id` is null, `enforce_cms_menu_parent` returns immediately, while its children retain `location='header'` and still reference it. The same root can be assigned beneath another root, making its existing children point to a parent that is no longer a root. The builder does not inspect children before either edit, and the trigger does not validate rows that reference `new.id`, so both operations recreate unrenderable hierarchy after the one-time normalization. Enforce the invariant from the parent side as well, either by rejecting the edit or updating affected children in the same transaction.

## Sanitized CMS delivery and explicit banner placements

`storefront_cms_payload` remains a `SECURITY DEFINER` read model with an empty search path that returns active/scheduled CMS content and only named storefront settings. The migration drops public CMS/settings policies and revokes anonymous direct selection, while the browser adapter reads CMS through the sanitized RPC.

The builder’s `home_hero`, `home_promo`, and `catalog_top` values correspond to the hero carousel, below-hero promo area, and server-backed catalog/category header respectively. Their targets use the guarded navigation path.

## Partial publish outcomes, request ordering, and ProductCard controls

Bulk inventory publishing derives failed IDs from per-product results, displays each failure, and keeps failed products selected after candidate refresh. The inventory panel and product catalog use request generations to discard stale responses; product filters reset to page one, and the server catalog similarly ignores superseded fetches.

The product-opening overlay and favorite button are sibling controls with separate accessible names and stacking layers. Favoriting therefore remains independent from product navigation.

## Validation scope

Production builds passed for `@texnobazar/storefront` and `@texnobazar/superadmin`. No test files were created, as requested. The workspace has no `.git` metadata, so `git diff main` could not be reproduced; this pass compared the current files with the prior review artifact and requested behavior list.
