# Receipt-bound branch-transfer ownership and settlement

The change keeps newly shipped units on the source branch until destination receipt, prices new transfer lines from canonical wholesale values, and supports transfer-scoped payments before debt creation. Receipt moves inventory, creates the branch debt, and attaches prepayments in one transaction. The transfer lock serializes payment and receipt, but the migration cannot run over existing payments or convert existing unsettled transfers to the new valuation and ownership rules. The richer transfer response also crosses a broader role boundary than settlement mutation.

Watch for: **[confirmed]** the migration fails when existing debt payments are present; **[confirmed]** pre-existing unsettled transfers retain noncanonical principal; **[confirmed]** legacy in-transit units remain outside source balances before receipt; **[confirmed]** UZS wholesale values can be labeled USD/EUR; **[confirmed]** sellers and warehouse staff can receive full payment records through the transfer detail RPC.

**Verdict**: NEEDS_CHANGES

## High-level view

New transfers retain their source location and balance-counted status through shipping. **[confirmed]** The legacy compatibility path accepts old ship-time movement state without migrating it, so already-shipped units still violate the receipt ownership boundary.

Settlement is transfer-scoped before receipt and debt-scoped afterward, with both mutations locking the transfer first. **[confirmed]** Replay equivalence omits the payment date, and **[confirmed]** malformed initial-payment objects can silently become no-payment creates.

Wholesale enforcement applies only to future inserts and compares an undenominated number. **[confirmed]** Existing open lines remain noncanonical, **[confirmed]** UZS catalog values can be assigned to USD/EUR debt, and **[likely]** receipt writes wholesale value into inventory cost fields.

Only creditor managers/accountants can record settlement. **[confirmed]** Any seller or warehouse user with either branch can nevertheless receive complete payment rows from the security-definer transfer detail RPC.

**[confirmed]** The search RPC can be made unbounded with a null limit and its UI formats prices through USD regardless of denomination. **[likely]** The exported create helper also breaks its prior third-argument contract, while **[confirmed]** the existing smoke migration asserts the superseded ship-time ownership behavior.

## Existing payment rows stop the migration before trigger replacement

**[confirmed]** `20260902800000_branch_transfer_settlement.sql` backfills `debt_payments.transfer_id` at lines 8–11, while the old `debt_payments_immutable` trigger remains installed until lines 56–58. Existing row updates invoke `reject_mutation()`, so a database with payment history aborts the migration. Replace or temporarily remove the old trigger before backfill, then install the narrowed one-time attachment guard after conversion and validation.

## Legacy transfers keep old principal and ownership semantics

**[confirmed]** The wholesale trigger is `BEFORE INSERT` only. Existing requested, approved, and in-transit lines keep earlier client-selected or cost-based `unit_price`, and `transfers.total_amount` is not recomputed. Migrate unsettled lines and totals under controlled trigger handling, or quarantine them until recreated.

**[confirmed]** Old shipping changed units to `in_transit` and wrote `transfer_out`, removing them from balances that count only `available`, `reserved`, and `returned`. The new receipt function accepts that state at lines 280–282 but does not restore source ownership before receipt. Reconcile legacy in-transit state or deploy only after draining all transfers in transit.

## Wholesale denomination and inventory valuation diverge

**[confirmed]** Catalog wholesale prices are stored and displayed as UZS, while `TransferWorkspace.jsx` permits UZS, USD, or EUR and SQL compares only the numeric value. The same `1,000,000` can become 1,000,000 USD debt. Derive transfer currency from catalog denomination, or convert through a server-owned rate and persist the source amount and rate.

**[likely]** Receipt writes `v_line.unit_price` to `inventory_movements.unit_cost` for both movements. That line value is wholesale selling price, while batch `unit_cost` and product `cost_price` are separate valuation fields. Use batch/product cost unless transfer movement cost has explicitly been redefined; retain settlement value in transfer/debt fields or metadata.

## Transfer detail bypasses the financial read boundary

**[confirmed]** `get_branch_transfer` authorizes through `require_transfer_access`; `can_access_branch` includes seller and warehouse roles. Its new `payments` property returns `to_jsonb(debt_payments)`, including reference, notes, `created_by`, and idempotency key. Gate settlement fields behind financial roles, return a redacted projection, or split them into a separately authorized RPC.

## Payment request identity is incomplete

**[confirmed]** Replay compares amount, currency, method, reference, and notes but not `paid_at`. Reusing a key with another date returns success while retaining the first date. Include a normalized date in a stored request fingerprint; null/server-time requests cannot safely recompute `now()` during replay.

**[confirmed]** `create_branch_transfer_with_payment` calls payment only when `coalesce(v_amount,0)>0`; a nonempty object with missing, zero, or negative amount silently means no payment. Reject every invalid nonempty payment object and reserve null or an explicitly supported empty object for no payment.

## Search and package contracts escape the current UI assumptions

**[confirmed]** `p_limit not between 1 and 50` evaluates unknown for null, and `LIMIT NULL` is unbounded. Reject null or use a bounded `coalesce` before validation and query execution.

**[likely]** `createBranchTransfer(header, lines, idempotencyKey)` became `createBranchTransfer(header, lines, initialPayment, keys)`. The repository caller is updated, but downstream callers passing a UUID in slot three send a JSON scalar payment and fail. Preserve a compatibility overload or version the contract.

**[confirmed]** `TransferSearchResults` formats every price as USD and strips the suffix. Pass the server-owned denomination and render it explicitly.

## Existing smoke coverage validates the opposite boundary

**[confirmed]** `20260110000000_branch_transfer_smoke_validation.sql` expects ship to set `in_transit`, write `transfer_out`, and decrement source `on_hand`. No new test covers existing-payment migration, legacy state conversion, prepayment attachment, receipt/payment races, changed-date replay, ACL redaction, or rollback. Add post-change validation seeded with pre-migration rows and assert source balance remains unchanged until receipt.
