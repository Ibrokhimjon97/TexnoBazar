## UZS catalog values still become USD transfer debt

**[confirmed]** `InventoryWorkspace.jsx` multiplies USD-displayed retail, wholesale, minimum, and cost inputs by the current USD/UZS rate before persistence. Receipt submission sends that converted `wholesale_price`, and neither `stock_batches.wholesale_price` nor `products.wholesale_price` stores a denomination.

The settlement migration reads `coalesce(b.wholesale_price,p.wholesale_price)` without conversion, writes it into legacy `transfer_lines.unit_price`, changes the transfer currency to USD, and returns the same value as USD in new-transfer lookup/search. Receipt creates USD branch debt from that total, so a stored 12,000,000 UZS wholesale value becomes 12,000,000 USD.

Persist a denomination or enforce one canonical storage currency at every price write. Convert legacy UZS values through an explicitly selected, auditable rate before setting transfer currency to USD, and derive future USD transfer values server-side from the same model.

## Replacement lifecycle still lacks executable migration validation

**[confirmed]** `20260110000000_branch_transfer_smoke_validation.sql` expects ship to set units to `in_transit`, create `transfer_out`, and reduce source `on_hand`. It runs before `20260902800000_branch_transfer_settlement.sql` on a fresh database and is not repeated, so it cannot validate the replacement lifecycle.

No later validation seeds existing payment rows, requested/approved/in-transit transfers, or pre-receipt payments before applying conversion. Add a post-settlement smoke migration covering payment backfill, legacy repricing and source restoration, unchanged source balance through ship, receipt-time movement/debt attachment, replay with changed `paid_at`, and financial-role redaction. Local execution was unavailable because Docker was not running.
