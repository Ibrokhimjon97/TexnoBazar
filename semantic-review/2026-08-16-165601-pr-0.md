# Browser data workflows against the complete business migration

The reviewed modules expose storefront, operations, delivery, administration, and realtime behavior through the data-package barrel. RPC names and argument keys align with `20260113000000_complete_business_workflows.sql`, but the package still violates two server contracts: its public health check uses revoked table access and one of its duplicate order helpers omits mandatory idempotency. Delivery proof has no repository-side endpoint contract, while CMS realtime and CSV export leave narrower correctness and safety gaps. None of these boundaries has targeted regression coverage.

Watch for: **confirmed** public health checks report false outages; **confirmed** one exported order helper is rejected without an idempotency key; **likely** delivery proof depends on a missing external endpoint contract; **confirmed** some CMS payload changes never trigger refresh; **confirmed** CSV formula escaping misses control-prefixed cells.

**Verdict**: NEEDS_CHANGES

## High-level view

The migration removes anonymous table access in favor of sanitized storefront RPCs. `getConnectionStatus` still probes `products` directly, turning the expected anonymous permission denial into a false outage result.

The barrel exposes both singleton-client and caller-supplied-client order APIs. One generates the replay key required by the migration; the other sends `null` by default and is rejected before creating an order.

Delivery-proof upload is split between HTTP and the courier status RPC, but the HTTP endpoint and response shape are absent. Delivery ownership, server-side file validation, and production of the required HTTPS proof URL therefore remain unverifiable.

CMS realtime covers only banners, home blocks, and products, while the storefront payload also contains pages, promotions, menu items, and settings. The omitted resources are absent from the migration’s realtime publication too, so changes remain stale until another refresh.

CSV export misses dangerous formulas preceded by whitespace or control characters. No targeted tests exercise the RPC defaults, upload contract, realtime coverage/teardown, or CSV behavior.

<summary>Details</summary>

## Public connectivity bypasses the RPC-only storefront boundary

`getConnectionStatus` in `index.js` directly selects `products`. The migration’s final grants revoke all anonymous table access and allow anonymous callers only `storefront_catalog`, `storefront_cms_payload`, and `create_online_order`, so a healthy unauthenticated deployment returns a permission error that the helper converts to `{ ok: false }`. This false-outage behavior is **confirmed** by `index.js:33-47` and the migration’s public allow-list.

## Two order APIs disagree on the mandatory replay key

`storefront.js` exports `submitOnlineOrder` with a `crypto.randomUUID()` default, while `index.js` exports `createOnlineOrder(client, payload)` and maps an omitted key to `null`. Because `create_online_order` rejects null or blank `p_idempotency_key`, `createOnlineOrder(client, payloadWithoutKey)` deterministically fails; this is **confirmed** by `storefront.js:6`, `index.js:50-60`, and migration lines 692-699. Consolidating the wrappers around one contract prevents further drift between the two client surfaces.

## Delivery proof depends on an undefined trust-boundary contract

`uploadDeliveryProof` trusts browser-declared MIME for its client check, posts multipart fields named `deliveryId` and `file`, and accepts any successful JSON shape. No `/api/media/delivery-proof` implementation or route registration exists in the repository, while the status RPC requires a nonblank HTTPS `p_proof_url`. The flow is **likely** to 404 in a repository-only deployment or leave callers guessing which response property is the URL; an external route would need to disprove that and verify bearer authentication, active-courier ownership, server-observed type/size, and response shape.

## CMS payload and realtime publication cover different resources

`storefront_cms_payload` returns banners, home blocks, menu items, promotions, pages, and public settings. `subscribeCms` listens only to `cms_banners`, `cms_home_blocks`, and `products`, matching the migration’s limited publication. It is **confirmed** that page, promotion, menu, and setting edits produce no event through this helper, leaving long-lived sessions stale unless another path refreshes the payload.

## CSV quoting does not neutralize all spreadsheet formulas

`safeCell` prefixes an apostrophe only when the raw first character is `=`, `+`, `-`, or `@`. A tab or spreadsheet-trimmed whitespace can precede one of those markers and is emitted unchanged; CSV quoting does not prevent formula interpretation after import. This is **confirmed** by `admin.js:20`; sanitize dangerous prefixes after leading control/whitespace characters.

## Boundary behavior has no regression coverage

Repository test search found no tests for `rowsToCsv`, `uploadDeliveryProof`, `subscribeTable`, `submitOnlineOrder`, `saveCmsRecord`, or the operations wrappers. This **confirmed** gap leaves anonymous grants, mandatory RPC defaults, multipart response shape, publication symmetry, teardown calls, and spreadsheet escaping unguarded.
