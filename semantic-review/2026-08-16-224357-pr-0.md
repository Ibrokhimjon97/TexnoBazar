Courier distance reporting now routes authenticated GPS writes through a constrained RPC, preserves completed attempts across reassignment, and computes distance inside attempt-specific route windows. Historical reports no longer depend on couriers or branches remaining active, and the client updates local route state before starting GPS. ## High-level view

The tracking trust boundary is now the RPC: direct authenticated mutations are revoked, the permissive insert policy is removed, and accepted writes require the caller's active courier assignment to an `in_transit` delivery in the matching branch.

Terminal outcomes are snapshotted before the reusable delivery row can be reassigned. Distance joins GPS points to bounded delivery/courier attempt windows and partitions lag calculations by attempt, while fact-derived courier/branch pairs keep inactive historical work visible.

The courier client changes its local delivery to `in_transit` before enabling `trackingId`, removing the stale-state auto-start race. Courier, manager, and administrator consumers continue to receive one shared aggregate contract under self, branch, and global authorization scopes.

## Attempt facts and route windows preserve reassignment boundaries

`capture_delivery_attempt` runs on the terminal status update and stores the courier, branch, outcome, assignment time, route start, and completion time in the same transaction. Existing terminal rows are backfilled before reporting switches sources; current reports then combine those terminal facts only with non-terminal delivery rows, avoiding terminal double counts. Route lag is partitioned by a unique attempt/current-assignment key after matching both delivery and courier inside the route window, so neither an old courier's endpoint nor an earlier attempt can seed the next route segment.

## Database privileges keep internal aggregation behind scoped wrappers

Authenticated table mutation on `courier_tracking` is revoked and its insert policy is dropped; server-generated timestamps and assignment/status checks therefore cannot be bypassed through the table API. Public, anonymous, and authenticated execution is removed from trigger and internal aggregation functions, while `get_courier_stats`, `list_courier_performance`, and `insert_courier_tracking` are re-granted explicitly. The wrappers enforce active-courier self scope, manager branch scope, or global administrator scope before invoking the internal `SECURITY DEFINER` row generator.
