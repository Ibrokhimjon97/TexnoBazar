## Account ownership merge chegarasi user identity bilan bog‘lanmagan

`refreshAccount` request boshlangandagi user IDni response qabul qilishdan oldin tekshiradi, lekin `account` state’ining o‘zida owner ID saqlanmaydi (`apps/storefront/src/App.jsx:140-151`). Auth user A’dan B’ga bir commitda o‘zgarsa, A account state’i render closure’da qoladi. Oldingi userni tozalovchi effect `setAccount(null)` qiladi (`App.jsx:185-196`), ammo keyingi merge effect ayni commitdagi stale `account` bilan B markerini o‘rnatib, A cart/favorite yozuvlarini authenticated write’larga uzatadi (`App.jsx:199-218`).

Bu **[confirmed, high]** cross-account data corruption va privacy muammosi: keyingi render cleanup’i boshlangan RPC yozuvlarini bekor qilmaydi. `account`ni `{ userId, data }` ko‘rinishida saqlash, merge’ni `account.userId === session.user.id` bilan gate qilish va write batch oldidan `activeUserId.current === userId`ni qayta tekshirish kerak.

Unknown product ID hydration cache’da topilmagan IDlarni o‘chirmaydi va faqat authoritative product qaytgach stock reconciliation qiladi. Account owner gate tuzatilgach bu non-obvious preservation qarori maqsadga mos ishlaydi.

## Typed attribute facetlari va dimensionlararo countlar

Facet payload esa `val.value`ni `#>> '{}'` bilan textga aylantiradi (`...sql:313-320`). Facet JSON’da typed `val.value`ni saqlab, display/sort textni alohida hisoblash kerak.

## Filter requestlari response tartibini nazorat qilmaydi

`ServerCatalog` har query/filter o‘zgarishida async RPC boshlaydi va response kelganda unconditional `setResult` qiladi (`apps/storefront/src/App.jsx:456`). **[confirmed, medium]** Sekin eski request tez yangi requestdan keyin tugasa, UI yangi filter holati yonida eski items/facetsni ko‘rsatadi; eski “Yana yuklash” requesti yangi natijaga oldingi sahifani append qilishi ham mumkin.

Monotonic request ID/ref yoki abortable transport bilan faqat latest filter generation response’iga state yozishga ruxsat berish kerak. Append response boshlangandagi serialized filter key va page predecessor bilan ham tekshirilishi kerak.

## List projection detail payloadni har sahifada qayta quradi
